# Сборка экранов флоу подачи — конструктор

Как из компонентов Larixon Mobile DS собирается экран флоу подачи (Post-ad). Экран подачи — **не уникальный макет, а сборка**: фиксированный скелет зон + правило вертикального ритма + ограниченный набор компонентов-кирпичей. Дизайнер и разработчик **собирают** экран из конструктора, а не рисуют каждый заново.

Смежные документы: [spacing-semantic.md](./spacing-semantic.md) (токены отступов), [composition-rules.md](./composition-rules.md), [DESIGN-TOKENS.md](./DESIGN-TOKENS.md).

---

## 1. Скелет экрана (зоны сверху вниз)

Экран — вертикальный auto-layout контейнер. Зоны фиксированы, порядок фиксирован:

| Зона | Компонент | Обяз. | Роль |
|---|---|---|---|
| StatusBar | `StatusBar` | ✅ | Системная строка |
| Top App Bar | `Top App Bar v2` | ✅ | Заголовок шага + назад |
| Progress | `Progress` (Top progress) | ⬜ опц. | Индикатор шага флоу. Есть не на всех экранах (напр. первый экран поиска категории — без него) |
| **Content** | frame (VERTICAL auto-layout) | ✅ | **Тело экрана. Скроллится. Сюда собираются блоки** (§2–§5) |
| CTA | frame (sticky bottom) | ⬜ | Нижняя кнопка(и) шага («Next step» / «Показать») |
| Home Indicator / Keyboard | — | ⬜ | Системные |

**Sticky/floating зоны** (Top App Bar, CTA, если контент скроллится под ними) — на `Surface/Surface Primary` (в Dark даёт elevation над `Background/Primary`). Inline-кейс — `Background/Primary`. См. [COLOR-PALETTE.md §3.2](./COLOR-PALETTE.md).

---

## 2. Верхний отступ Content

**Первый блок Content всегда отстоит от Progress/Top App Bar на `12`** (`spacing/3`). Это выравнивает верхнюю линию контента по всем экранам флоу и не даёт блоку «прилипнуть» к прогресс-индикатору.

- Применяется к **любому** первому блоку: поле, поиск, заголовок, форма.
- **Исключение — экраны-списки** (выбор из List item: Body type, Color, Fuel type и т.п.): список идёт **впритык** (`padТop = 0`), это edge-to-edge паттерн.
- ⚠️ Значения ≠ 12 (напр. 16) на контентных экранах — **аномалия**, приводить к 12.

Токен: пока `spacing/3` напрямую. Кандидат на семантику — `screen/content-top = 12` (см. §8).

## 3. Вертикальный ритм Content — ядро системы

Блоки в Content расставляются по **относительной плотности**, а не равномерным gap: **связанное — теснее, разное — свободнее**. Это инвариант. Конкретные значения берутся из **вертикальной шкалы gap** и подбираются под плотность экрана — это **НЕ фиксированная пара чисел**.

| Отношение | Шаг | Типовое значение (флексит по плотности) |
|---|---|---|
| Внутри одной группы / сущности | `within` (меньший) | `12` (`stack/gap-loose`); плотнее — `8` |
| Между разными сущностями | `between` (больший) | `24`; теснее/свободнее — `16` / `32` |

**Ключевое правило — `within < between`** (шаг внутри группы всегда меньше, чем между группами). Абсолют — вопрос плотности конкретного экрана: плотная форма может жить на `8 / 16`, комфортная — `12 / 24`, hero-экран — `16 / 32`. Систему задаёт **отношение**, а не числа.

**Реализация (важно для разработки):**
- Связанные блоки **оборачиваются в под-контейнер** (VERTICAL) с `within`-шагом.
- Content между группами — `between`-шаг.
- НЕ ставить равномерный `gap` на все блоки Content — это слепляет разные сущности в один плотный стек (типичная ошибка).

```
Content (VERTICAL, gap = between)     ← между сущностями (напр. 24)
 ├─ Group «Ввод цены» (VERTICAL, gap = within)  ← внутри группы (напр. 12)
 │   ├─ Валюта (chips)
 │   └─ Цена От/До
 └─ Возможен торг (Switch row)        ← отдельная сущность
```

---

## 4. Что считать «сущностью» — триггеры разделения (24)

Разделяем `24`, когда на экране **≥2 разных сущности**. Триггеры:

- **Разные секции** — характеристики vs контакты (summary, Contacts).
- **Альтернативные методы** — «вставить ссылку» vs «загрузить файл» (Add video).
- **Отдельный атрибут/настройка** — «возможен торг» рядом с полем цены (Set a price).

Оставляем `12` (одна сущность), когда блоки — части одного целого:

- Поле + его подсказка/лейбл (Description: helper + Textarea).
- Пара одной задачи (Add Vehicle Registration: front/back одного документа).
- Значение + его модификатор (валюта относится к цене → внутри группы «ввод цены»).

---

## 5. Когда правило НЕ применяется (single-concern)

Система **не трогает** одно-концернные экраны — группировать нечего, blast radius узкий:

| Архетип | Пример | Ритм |
|---|---|---|
| Одно поле | Mileage, Power | одиночный блок, `padTop 12` |
| Поиск | Post an ad, Select location | `Search v2`, `padTop 12` |
| Текст | Description | подсказка + `Textarea` = 1 группа (12) |
| Медиа | Add photo | подсказка + грид = 1 группа (12) |
| Список выбора | Body type, Color | `List item ×N`, `gap 0`, `padTop 0`, дивайдеры |

## 6. Компоненты-кирпичи — выбор контрола под задачу

| Задача | Компонент | Анти-паттерн |
|---|---|---|
| Ввод текста/числа | `Input v2` (диапазон — два Input v2 «От»/«До») | — |
| Поиск | `Search v2` | — |
| **Выбор значения из 2–4 коротких опций** | **`Chips` single-select** (Active=Yes на выбранном) | ❌ «Segmented control» — это **underline-табы = навигация по вью**, не выбор значения. ❌ dropdown — прячет варианты |
| Выбор значения, список растёт (>4) / нужны иконки/описания | `List item` + `Radio` (single) / `Checkbox` (multi) | — |
| Вкл/выкл атрибут | `Switch` в `List item` | — |
| Многострочный текст | `Textarea` | — |
| Выбор значения со сменой (напр. валюта у одного поля) | `Input v2` (ReadOnly) + trailing `chevron` → поверхность (`Sheet` / `Context Menu`) | prefix-слота в Input v2 нет — символ валюты не пихать в поле |

## 7. Архетипы (готовые рецепты сборки)

| Архетип | Content | Ритм |
|---|---|---|
| **Одно поле** | `[Input v2]` | padTop 12 |
| **Форма (цена)** | Group`[Chips валюта + Input v2 От/До]` + `[Switch торг]` | within/between (типово 12/24) |
| **Длинная форма (сводка)** | Group`[характеристики ×N]` + `[контакты]` | within внутри / between между секциями |
| **Альтернативные методы** | `[Input v2 ссылка]` + Group`[заголовок + область загрузки]` | between между методами / within внутри |
| **Текст / Медиа** | `[подсказка + поле]` | within (одна группа) |
| **Список** | `[List item ×N]` | gap 0, padTop 0 |

> Числа в примерах (12/24) — типовая пара для комфортной плотности, **не закон**. See §3: `within < between`, значения — по плотности экрана.

## 8. Токены — нужна шкала с разнообразием, а не фикс

Ритм требует **шкалы вертикальных gap с разной плотностью**, а не двух зашитых чисел — `within` и `between` подбираются под экран (§3). Что есть в `stack/*` ([spacing-semantic.md](./spacing-semantic.md)):

- `stack/gap-tight = 4`, `gap-default = 8`, `gap-loose = 12` — покрывают **within-group** на разных плотностях. ✅
- Для **between-group** шкала **обрывается на 12** — нет шагов `16 / 24 / 32`. Пробел: между сущностями сейчас некуда биндиться семантикой, только голый primitive.

**Предложение — продлить вертикальную шкалу вверх** (имена на обсуждение):

| Токен | Значение | Alias | Роль |
|---|---|---|---|
| `stack/gap-xloose` | 16 | `spacing/4` | between на плотных экранах |
| `stack/gap-2xloose` | 24 | `spacing/6` | between типовой |
| `stack/gap-3xloose` | 32 | `spacing/8` | between на hero / airy |

Тогда `within` и `between` оба берутся **из одной шкалы**, под плотность, а не хардкодятся. Верхний отступ Content (§2) — тоже с этой шкалы (кандидат `screen/content-top`).

> **Статус:** proposal. Не завожу без подтверждения (по правилу — не плодить токены без надобности; см. `spacing-semantic.md §Правила`). До заведения — bind на primitives `spacing/4..8`. Точные имена/шаги — за DS-командой.

## 9. Для разработки

- **Content = скролл-контейнер** (Compose `Column`/`LazyColumn`, SwiftUI `ScrollView`+`VStack`). Группы сущностей — **вложенные контейнеры** со своим `spacing`.
- **Отступы — из токенов, не хардкод.** Внутри группы — `stack/gap-loose`; между группами — `stack/gap-section` (после заведения); верх — `screen/content-top`.
- **Правило проверки на ревью:** если в теле экрана ≥2 разных сущности, а `gap` равномерный — это не собрано по системе. Обернуть в группы + 24 между.
- **Списки** — свой ритм (item height + divider), form-spacing к ним не применять.
