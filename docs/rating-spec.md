# Rating (звёзды) — спецификация

Звёздный рейтинг Larixon Mobile. Два режима: **отображение** среднего балла (read-only, напр. в `StatisticBlock`) и **ввод** оценки пользователем (`AppRatingStars`).

**Категория:** Atom.
**Статус:** v0.1 (2026-11-01, по сверке Android). Figma-компонент — в планах; спека фиксирует канон поведения заливки, о котором спросила разработка.

---

## 1. Шкала

- **5 звёзд**, слева направо.
- Значение — число `0.0…5.0`. В отображении показывается до **1 знака** после запятой (напр. `4.2`).

---

## 2. Отображение среднего балла (read-only) — **дробная заливка**

**Канон: заливка пропорциональна значению (fractional), НЕ округление вверх и НЕ только половинки.**

Для значения `V`:
- `floor(V)` звёзд — залиты полностью;
- следующая звезда залита на **дробную часть** `V − floor(V)` (напр. `4.2` → 4 полных + 5-я залита на 20% по ширине слева направо);
- остальные — пустые.

**Пример:** `4.2` рисуется как ★★★★⯪ (четыре полных + пятая на 20%), **не** как ★★★★★.

Реализация заливки — клип/маска «залитого» слоя звёзд поверх «пустого» по проценту `V/5 × 100%` (стандартный overlay-clip), либо per-star дробная заливка. Половинки (`0.5` шаг) — **не** канон для отображения: теряется точность (`4.2` и `4.4` стали бы одинаковыми).

> Это закрывает баг сверки: `StatisticBlock` заливал звезду целиком с округлением вверх (`4.2 → 5`), что завышало оценку. Канон — честная дробная заливка.

---

## 3. Ввод оценки пользователем (`AppRatingStars`, интерактивный)

- Пользователь выбирает **целыми звёздами** (тап по звезде N → оценка = N). Дробный ввод и половинки при ручной оценке **не** используются (нет точного аффорданса попасть в «пол-звезды» пальцем).
- Выбранные звёзды — залиты полностью, остальные — пустые.
- Полу-/дробная заливка — только для §2 (отображение агрегата).

---

## 4. Токены

| Элемент | Токен | Примечание |
|---|---|---|
| Звезда (filled) | `ic_star_fill` | цвет — см. ниже |
| Звезда (empty) | `ic_star` (outline) | контур |
| Цвет залитой звезды | **уточнить у built-компонента** (кандидат — тёплый акцент; в DS нет отдельного «звёздного» токена) | не заводить новый токен без необходимости |
| Цвет пустой звезды | `Text&Icon/Tertiary` или `Border/Default` | нейтральный |
| Размер звезды | `size/*` по контексту (в `StatisticBlock` — компактный) | — |
| Gap между звёздами | `spacing/*` | — |

> Точные цвет/размер — зафиксировать при сборке Figma-компонента и сверке с продуктовыми экранами. Здесь канон — **механика заливки**, а не визуальные значения.

---

## 5. Открытое

1. **Figma-компонент + строка в реестре** — завести (сейчас нет ни спеки-строки, ни компонента; `AppRatingStars` и `StatisticBlock` живут только в Android-коде).
2. **Точный цвет залитой звезды** — определить на сборке; не плодить токен, если подходит существующий акцент.
3. **Веб-консистентность** — у веба звёзды не вынесены в Web DS (нет в Storybook); при появлении общего решения — свериться. Пока канон задаёт мобилка (этот документ).
