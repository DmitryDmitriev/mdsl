# Elevation / Shadow — аудит same-BG кейсов (CD-6799)

> Статус: **первый проход, same-BG часть.** Входит в CD-6799 «Shadow — пересборка elevation-системы (floating + same-BG card)».
> Дата: 2026-10-25. Источники: `elevation-spec.md`, прод-файл `PI3XrUDuoGyK4aXkqyzYoB` (страницы «🔍 Elevation Audit», «🔍 Modals Audit»), reference-кейс из `Sellers-Cabinets` (`a592rafno0osDOPXyzhpQv`).

## TL;DR

- **Текущий канон прямо запрещает тень на карточках** (правило 5) и отделяет шторки/модалки скримом без тени (правило 4). В dark тени выключены полностью.
- **Реальный контрпример** (reference из тикета): XL-карточка допродажи — **белая на белой подложке** (`Background/Primary` на `Background/Primary`), отделяется `border 1px` **+ натянутым `Elevation/Top`**. `Elevation/Top` семантически = тень sticky-бара, не карточки. Отдельного «card»-уровня подъёма **нет** → импровизация.
- **Same-BG проблема возникает ТОЛЬКО** там, где карточка обязана делить тон с поверхностью (нельзя занять вторичный тон) **и** она не над скримом. Шторки/диалоги над затемнением — **не проблема** (скрим работает).
- **Решение по семантике — следующий шаг.** Главное ограничение: в dark тени нет, значит разделение same-BG обязано работать поверхностью/бордером в обеих темах, а тень — только light-усиление.

---

## Что такое «same-BG» (определение для аудита)

Контейнер-карточка, у которого `fill` совпадает с `fill` родительской поверхности → контраста по фону нет → край карточки не читается. Отделить можно только: (а) ступенью поверхности, (б) бордером, (в) тенью (light-only), (г) скримом — если это оверлей над контентом.

## Текущий канон (`elevation-spec.md`)

| | Правило |
|---|---|
| Токены | 3 шт: `Elevation/Top` (sticky верх ↓), `Elevation/Floating` (ambient, плавающие), `Elevation/Bottom` (sticky низ ↑) — **все про края/плавание, не про карточку** |
| Правило 4 | Модалки, drawers, dropdowns, bottom sheets — **overlay без тени** |
| Правило 5 | Карточки, Product Card, GridCard — **без теней**, дифференциация `border/default` или поверхностью |
| Dark | Ни один Elevation-стиль не применяется; иерархия только цветом поверхности |

Апрельский аудит (2026) заключил: «карточки физически не приподняты над контентом» → 3-токенная модель. CD-6799 ревизует именно этот вывод для same-BG.

## Подтверждённый кейс (reference)

**XL-карточка допродажи**, `Sellers-Cabinets` node `11540:47056`:
- `328×124`, `cornerRadius 16`, fill = `Background/Primary` (белый).
- Подложка экрана `F1c · XL` (`11496:44261`) = тоже `Background/Primary`. → **white-on-white**.
- Отделяется: `stroke 1px` **+** `effectStyle Elevation/Top` (`0 4 16 /8%` + `0 0 6 /8%`).
- Наличие и бордера, и тени → **одного бордера на white-on-white дизайнеру не хватило**, а «card»-токена нет → взял `Elevation/Top` (тень sticky-бара).

Это ровно сценарий (б) из тикета: вторичный тон занять нельзя (карточка — промо-акцент на чистом экране), скрима нет (не оверлей).

## Dark-ограничение (ключевое для семантики)

Тень в dark выключена. Значит:
- Если в light отделять тенью, а в dark — поверхностью/бордером, получается **несогласованная семантика** (разный механизм по темам).
- Семантика same-BG card должна быть **surface-first в обеих темах** (ступень поверхности и/или бордер), а тень — **light-only усиление** поверх, не единственный носитель контраста.

## Открытые вопросы (на решение Дмитрия — до проектирования токенов)

1. **Вводим ли «card»-уровень подъёма?** Предложение: `card` = база `border/default` + ступень поверхности, где возможна, + **light-only** мягкая тень для white-on-white. Не переиспользовать `Elevation/Top`.
2. **Или** запрещаем white-on-white карточки и обязываем вторичную поверхность? Тогда вложенные карточки на вторичной поверхности снова без контраста → потребуется третичный тон поверхности.
3. **Floating-часть тикета (а)** — уже закрыта `Elevation/Floating`, отдельный токен не нужен (подтверждено спекой).

## Предложение по семантике (на решение Дмитрия)

Переформулированный вывод: вопрос не «должны ли карточки подниматься» — **они уже поднимаются**; вопрос в том, что **санкционированного токена нет**, поэтому это делается deprecated/ad-hoc стилями.

**Решение (подтверждено Дмитрием 2026-10-25): вводим `Elevation/Card`.** Оставляем Top/Floating/Bottom, затем мигрируем `Shadow/Sheet Active/Default` + `Elevation/Light/*` + чужие + 558 ad-hoc на канон.

### Проектное предложение по `Elevation/Card` (на подтверждение значений)

**Направление — вниз (карточка лежит на поверхности).** Важно: текущая `Shadow/Sheet Active` направлена ВВЕРХ (`y −8`) — это тень шторки, ошибочно натянутая на карточки. Card-тень должна быть мягкой вниз.

Сравнение с каноном (все #000):
| Токен | Layer 1 | Layer 2 | Роль |
|---|---|---|---|
| Elevation/Top | 0 4 16 /8% | 0 0 6 /8% | sticky-бар (есть «гало») |
| Elevation/Floating | 0 0 12 /8% | 0 2 4 /5% | плавающий контрол (ambient, без направления) |
| Elevation/Bottom | 0 −8 24 /10% | 0 −2 24 /8% | sticky низ (вверх) |
| **Elevation/Card (предл.)** | **0 2 4 /4%** | **0 4 12 /8%** | **карточка (мягко вниз)** |

(= ретро `[deprecated] Elevation/Light/3`, уже обкатан на 27 узлах; визуально непрерывная миграция.)

**Рецепт карточки (surface-first, тень — только light):**
- `fill` = `Surface/Surface Primary` (НЕ `Background/Primary`). В light = белый (= фон) → разделение несёт тень. В dark = `Zinc/800` на `Background` `Zinc/950` → **ступень поверхности** сама отрывает карточку, тень не нужна.
- light: `+ Elevation/Card`;
- dark: тени нет (канон) — работает surface-step;
- `border/default`: **опционален**, не обязателен (surface + тень достаточно). Оставляем для карточек поверх медиа/изображений, где нужен чёткий край.

Так **surface-токен закрывает dark, тень-токен закрывает light** — один механизм не тянет обе темы. Привязка `fill` карточек к `Surface Primary` заодно уводит их с легаси `Background Old/Primary` (сходится с миграцией палитры).

## Решение (финал, 2026-10-25)

Значения подобраны итеративно на живой XL-карточке (`57374:33997`):
- стартовали с 2 слоёв только вниз → верхний край растворялся на same-BG;
- 3 слоя (+ambient) → край держится;
- **финал: 2 слоя** — ambient `0 0 6 /6%` + глубина `0 4 12 /8%` (contact-слой убран: визуально не отличить, рендер на треть легче).
- **без обводки** (тень несёт весь контур).
- **dark — без тени** (подтверждено Дмитрием: два уровня сюрфейсов закрывают).
- **сетка/фид — не тень, а ступень поверхности** (перф: overdraw × N карточек на скролле).
